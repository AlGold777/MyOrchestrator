## Как провести Gate 0 (руками, ~1–2 часа)

Цель: доказать, что цикл «независимая волна → сжатие → атака → ремонт» находит **хотя бы
одно расхождение, невидимое в исходных независимых ответах**. Провал после одной итерации
оптимизации промптов = оркестратор не пишется.

1. **Независимая волна.** Одна идея → 6–10 моделям один и тот же вопрос, параллельно,
   никто не видит чужих ответов (обычный параллельный режим главной страницы подходит).
   Сохранить ответы как r01…r10.
2. **Сжатие.** Ответы (перемешанные, без имён моделей) → `gate0/prompts/compress.md` →
   Sonnet. Продублировать вторым синтезатором, расхождение кластеризаций записать.
3. **Узлы.** Из node_candidates собрать 10–15 узлов вручную по
   `gate0/node-templates.json` (валидны по `gate0/node.schema.json`).
4. **Волна ATTACK.** Каждый узел → 2–3 моделям через `gate0/prompts/attack.md`
   (соблюдать ротацию: узел не атакуется одним слотом две волны подряд). Сырые ответы
   сложить в wave-файл (формат в шапке `gate0/attack-wave-check.js`) и прогнать:
   `node gate0/attack-wave-check.js wave1.json` — скрипт даст замер Gate 3
   (JSON-валидность по слотам) и долю дублей.
5. **REPAIR.** Выжившие атаки → `gate0/prompts/repair.md` (другому слоту, не автору узла).
6. **Карта разломов — слепой протокол.** Выписать расхождения, НЕ глядя в исходные ответы
   шага 1; только потом сверить. Критерий успеха: ≥1 расхождение, которого в независимых
   ответах не видно.

Побочные замеры того же прогона: доля дублей атак (<20% → дедуп в v1 не нужен) и
первые честные цифры JSON-валидности по моделям (порог структурного пула: ≥70–75%
schema-valid с первой попытки).
