# Расследование торможения расширения — журнал

**Дата:** 2026-07-24
**Baseline:** LLM_Fable `a33b37f` (2.81.52)
**Симптом:** после отправки промпта моделям с обычной comparison-страницы (выбрал
модели → отправил) браузер нагружается, страницы открываются медленно.
**Референс:** LLM_Sol 2.81.25 (21 июля) — «летает» на том же сценарии.
**Статус:** локализован обязательный тяжёлый путь скрытой StateMap; исправлен.
Нужна контрольная проверка пользователем в реальном Chrome после reload extension.

---

## 1. Что применено в коде (три фикса) — content-scripts ОТКАЧЕНЫ

Применены как «безопасные» (меняют частоту, не семантику). Тесты 907/907 зелёные.
**Эффекта на торможение не дали** — впоследствии выяснено, что били не по причине
(content-scripts идентичны рабочей Sol, значит не источник регрессии).

| # | Файл | Изменение | Статус |
|---|---|---|---|
| 1 | `content-scripts/base-adapter.js` | Удалён дублирующий `setInterval(checkUrl, 250)` | **Откачено к HEAD** (снова = Sol) |
| 2 | `content-scripts/content-utils.js` `observeMutations` | rAF-coalescing callbacks | **Откачено к HEAD** (снова = Sol) |
| 3 | `results.js` `applyDebateSessionFilter` | rAF-coalescing DOM-sweep; синхронная версия как `applyDebateSessionFilterNow` | Осталась (Disput-feed, не content-scripts) |

Причина отката: раз content-scripts не источник торможения, правки в них — лишний
шум. Возвращены к состоянию до perf-попытки, побайтово идентичны LLM_Sol.

Версия → 2.81.52, запись в CHANGELOG.

## 3. Опровергнутые гипотезы других моделей

Три модели (GPT/Z.ai/Qwen) диагностировали по коду; главные гипотезы проверены и
не подтвердились для этого симптома:

- **«34 content-scripts — тяжёлый bundle»** (GPT/Z.ai) — обе версии грузят 34;
  Sol летает. Bundle size не причина торможения (может влиять на load-time, не на
  runtime после отправки).
- **`characterData` observers / applyDebateSessionFilter / polling loops** (Z.ai)
  — все в content-scripts, которые идентичны Sol. Реальны как неэффективность, но
  не источник регрессии.
- **storage-write шторм / clone-шторм / re-render шторм** (GPT/Qwen) — в
  disput-контуре, который при обычной comparison не активирован.

## 4. Моя методологическая ошибка (зафиксирована честно)

Предположил «регрессию внёс universal engine», потому что LLM_Sol содержит старые
runners (duel/triad/multi), а Fable — universal. Это **экстраполяция из наличия
файлов, а не доказательство**. Между 2.81.25 и 2.81.52 — десятки изменений
(universal, semantic-доки, UI-правки, Codex-коммиты); я выхватил самое крупное без
проверки. Пользователь справедливо это отметил. Также не проверял, что Sol «летает»
из-за кода, а не из-за чистого профиля.

Дополнительно: перенаправление — **семантический план (карта состояния) исключён**
by construction, т.к. это только документы, код им не менялся. Торможение —
до него.

## 5. Что осталось после исключения (два кандидата)

Всё, что **исполняется** при обычной comparison, между версиями идентично или
заменено на рабочее. Значит:

1. **Разовый парсинг 11 disput-модулей**, которые Fable грузит в `result_new.html`
   (Sol не грузит): `debate-orchestrator`, `debate-planner`, `debate-stage-executor`,
   `debate-orchestrator-persistence`, `debate-participant-registry`,
   `debate-storage-migrations`, `debate-protocol-transition-service`,
   `debate-artifact-pipeline`, `debate-draft-plan`, `debate-plan-revision`,
   `debate-policies`. Влияет на load-time, не очевидно — на runtime.
2. **Утечка памяти** — накопление → своп → глобальное «браузер грузится, страницы
   медленно, после работы». Не видна статикой, не ловится заменой одного файла.
   Кандидаты unbounded-контейнеров в universal-коде: `state.events`,
   `seenIdempotencyKeys` (Set), timeline-массивы.

## 6. Текущий шаг

**Heap snapshot до/после** (DevTools главной страницы → Memory → Heap snapshot,
сборка мусора перед каждым, сравнение Size + Comparison-вид по Delta). Глобальный
характер симптома («после работы всё медленнее») характернее для утечки, чем для
CPU одной страницы.

Ожидаемый ответ теста:
- Size растёт и не падает после GC → утечка; верхние строки Comparison назовут
  контейнер → точечный фикс.
- Size стабилен → не память; следующий тест — замена `result_new.html` на Sol
  (проверка гипотезы парсинга 11 модулей).

## 7. Не сделано / не проверено

- Runtime-профиль (Performance) — не снимался; заменён на heap-тест по характеру
  симптома.
- Бинарный поиск заменой `disput/` целиком и `result_new.html` — следующий шаг,
  если heap-тест отрицателен.
- Точная версия/дата, когда скорость упала — не установлена (сузила бы диапазон
  быстрее любого анализа).
- Прямые `new MutationObserver` на `body` с `characterData` в отдельных адаптерах
  (`content-qwen`, `content-deepseek`) — идут мимо общего `observeMutations`, не
  тронуты; но content-scripts исключены как причина.

## 8. Рекомендация

Коммит текущего состояния отложен: дерево содержит perf-правки (бившие не по цели)
поверх смешанных незакоммиченных изменений. Не фиксировать, пока причина не найдена,
иначе закрепим и неверные правки, и саму регрессию. После heap-теста — либо
точечный фикс утечки, либо переход к бинарному поиску заменой подсистем.

## 9. Локализованный тяжёлый путь и исправление

Обнаружена не разовая загрузка 11 universal-модулей, а обязательная работа после
загрузки страницы:

1. `results.js` создавал `DebateCaseStore`.
2. Без действия пользователя читал индекс и загружал последнее сохранённое дело.
3. Подписка передавала дело в `DisputStateMapView.render`.
4. `render`, хотя workspace карты закрыт через `hidden`, выполнял полную
   `DebateStateMap.project`, строил большой HTML через `innerHTML`, создавал все
   карточки и планировал layout связей.
5. При следующих semantic updates скрытая карта повторяла эту работу.

Это также объясняет, почему сравнение двух папок вводило в заблуждение:
`LLM_Fable` и `LLM_Sol` установлены из разных путей и имеют разные extension ID,
следовательно — разные `chrome.storage.local`. На проверенном профиле каталог
Fable занимал около 7,2 МБ, Sol — около 4,3 МБ. Быстрая Sol не воспроизводила
накопленное состояние Fable.

Исправление:

- закрытая карта хранит только последний входной aggregate/case;
- projection + DOM материализуются при открытии карты;
- несколько обновлений закрытой карты схлопываются: открывается только последнее;
- автоматическая загрузка последнего сохранённого дела при старте страницы
  удалена; дела по-прежнему доступны в селекторе карты.

Синтетическая проверка на 1500 artifacts:

| Вариант | Время init | Heap delta | DOM nodes | HTML карты |
|---|---:|---:|---:|---:|
| прежний eager render | 315,3 мс | 70,7 МБ | 10 568 | 920 915 chars |
| lazy render, карта закрыта | 8,0 мс | 1,0 МБ | 30 | 0 |

Regression-тест проверяет, что два hidden-update не вызывают projection, а при
открытии строится только последнее состояние. Полный Jest:
**153 suites / 908 tests / 0 failures**.

Ограничение доказательства: автоматизированный запуск отдельного unpacked
extension заблокирован текущим Chrome, поэтому end-to-end Task Manager замер
после фикса должен быть выполнен после `Reload` расширения в реальном профиле.

## 10. Дополнительные runtime/UI safeguards — 2.81.52

После локализации скрытой StateMap добавлены независимые меры для pipeline UI:

- сохранение cross-view UI при наборе текста выполняется debounce-очередью;
- resize-пересчёты объединяются через `requestAnimationFrame`;
- включение intermediate synthesis больше не пересоздаёт Canvas columns и
  connectors, а переключает только кнопку и DraftPlan stage;
- `New Pages` теперь расходуется только первой отправкой run, что убирает
  повторное создание вкладок на каждом раунде;
- lease heartbeat поддерживает активный run во время долгих ожиданий модели.

Эти изменения не заявляют полного browser performance proof. Для выпуска нужна
ручная проверка в Chrome после reload extension: три раунда, повторная отправка,
переключение Manual/Auto и просмотр Memory/Performance при необходимости.

Contract и test evidence: `docs/disput/TZ-runtime-ui-corrections-v1.0.md`,
`tests/release-log-regressions.test.js`; полный Jest после change set —
**153 suites / 911 tests**.
